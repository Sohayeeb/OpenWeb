Publish

Your PC is the host. That is the whole plan.

A site is a folder. In the OpenWeb app you publish it from this window: choose a folder, get an address. The key belongs to you, not to a name rented from somebody else.

OpenWeb does not need a deployment pipeline because there is nowhere to deploy to. The files stay on your disk. The node announces the drive's key on a DHT and answers readers directly. When you close the app, the site goes offline. When you open it again, the same address comes back.

Step one

Make a folder with an index.html.

my-site/
├── index.html
├── style.css
└── another-page.html

Static files only. No JavaScript runs in v1. Relative links and links that start with / both work. Or let the builder write the page for you.

Step two

Publish it from the browser.

open the publish page

Pick the folder in the native picker, or type its path. Each folder gets its own key and address; publishing a second folder never overwrites the first. Everything is stored in this app's data folder and restored on the next launch.

From a terminal, the same thing is openweb serve my-site.

Step three

Open the address.

Paste openweb://<address>/ into the address bar. The gateway resolves the key, joins the drive's topic, and speaks plain HTTP to the page view. It is the only bridge between the two worlds.

Step four

Let people find it.

There is no global index. A search engine on OpenWeb is a crawler plus an index file that one person owns. The app publishes its own sites into the local index automatically; add others from the sites page.

Then publish your index from shared index so other people can query what you crawled, or add your site to a signed directory.

Rules of the road

Small, signed, and accountable.

No adsNothing to sell means nothing to optimize for.
No trackersThe gateway sets no cookies and logs no visitors.
No AIPublish what you wrote. A human reviews the directory.
No take-backsYour key is your name. Revocation is a signed tombstone.
